## Summary
M0 ships no messaging, no accounts and no key storage. The only network endpoint is `GET /health`, and the MLS crate exists only as a spike that no shipped artifact links. There is therefore **no exploitable plaintext, key or auth issue today**, and **no critical or high findings**.

The build and deploy pipeline is in good shape: least-privilege workflow tokens, SHA-pinned actions, `persist-credentials: false`, registry credentials separated from Gradle, provenance verified before an owner-approved deploy, a forced-command SSH key with strict input validation, digest-pinned base images, Gradle locking plus SHA-256 verification, and repository filtering. There are no open Dependabot, code-scanning or secret-scanning alerts. All issues, PRs and commits are by the owner (no prompt-injection attempts found).

The findings are about **guard rails that are weaker than documented** (agent deny list, secret-file handling), **requirements at risk of being lost between the spikes and the M1/M2 issues**, and **design guidance for the M1 server work**, where the shared-VM decision makes some planned controls harder than the docs suggest.

## Checked and fine
- **No plaintext path to the server:** the server has only `/health`, and `HealthResponse` carries only a status and the protocol version. No `CallLogging` is installed; logback writes to stdout with Docker log rotation.
- **Crypto spike, correctly scoped:**
  - the ciphersuite is the ADR-0002 MTI suite
  - `PURE_CIPHERTEXT_WIRE_FORMAT_POLICY` and `padding_size` are set in both the create and the join config; the policy also makes incoming `PublicMessage`s, and with them external commits, get rejected
  - the GroupInfo from `add_members` is discarded, and the ratchet tree goes in the Welcome
  - the snapshot parser is bounds-checked and rejects duplicates, trailing bytes and a storage-version mismatch

  The known gaps (no member validation, `Debug`-string errors, immediate commit merge, untyped `process()`, plaintext snapshot, no zeroization, no cargo-audit) are documented in the crate and spike docs and carried into #11 (SEC-M0-2 covers the parts that aren't). No shipped artifact links the crate: `composeApp` and `shared` don't depend on it.
- **RNG on wasm32:** `cargo tree --target wasm32-unknown-unknown` shows getrandom 0.2 (`js` feature, via `rand_core` 0.6 / ed25519-dalek) and getrandom 0.4 (via OpenMLS's `js` feature). A missing backend fails compilation; it doesn't fail silently at run time. The release profile sets `panic = "unwind"`.
- **Deploy workflow:**
  - `permissions: {}` by default; the build job has no registry credentials and no caches; the push job runs no build code (the Dockerfile has no `RUN`)
  - the pushed digest is cross-checked with the registry
  - provenance is verified for the signer workflow, `refs/heads/main`, the source digest, and hosted runners only
  - inputs are passed through `env`, never interpolated into scripts
  - SSH uses pinned known_hosts, and the key is removed in an `always()` step
- **`deploy.sh`:**
  - strict `<40-hex> sha256:<64-hex>` input, `flock`, an ancestor-of-`origin/main` check, and pre-#7 commits are refused
  - the stage-2 hand-off is reachable only from stage 1 (sshd passes no arguments to forced commands)
  - `.env` is read without sourcing and rewritten atomically with mode 600
  - the health check pins `--proto =https` and the exact image
  - output is fixed status lines only
- **Containers:** read-only root filesystem, `cap_drop: ALL`, `no-new-privileges`, memory and pid limits, non-root UID 10001, a distroless digest-pinned base image, Postgres only on an `internal` network, no published ports, the password as a Compose secret file.
- **Caddy snippet:** no access log (`log_skip`, plus the documented check for global log blocks), a 1 MB body cap, HSTS, `nosniff`, `no-referrer`, an API-only CSP, frame denial.
- **CI and CodeQL:**
  - `pull_request` (not `pull_request_target`), read-only tokens, `persist-credentials: false`
  - the Gradle cache is written only from `main` and uses the `basic` provider; the verification-config tripwire runs
  - shellcheck and actionlint binaries are checksum-pinned
  - CodeQL's Rust extraction uses pre-fetched locked crates with `CARGO_NET_OFFLINE`, and the `security-extended` queries
- **Supply chain:**
  - Gradle locking for all configurations, and SHA-256 verification including the Node/Yarn/Binaryen archives
  - `FAIL_ON_PROJECT_REPOS` and exclusive repositories
  - Kotlin/JS runs Yarn with `--ignore-scripts` (KGP default since 1.6.10; not overridden here)
  - the wrapper checksum is pinned, and the `wasm-bindgen` crate/CLI pins are enforced by the hygiene script
  - Dependabot covers all five ecosystems, with a cooldown
- **Repository security settings (GET requests):** secret scanning and push protection are on, and so are Dependabot security updates. The default workflow token is `read`, and Actions can't approve PRs. Private vulnerability reporting is enabled. There are no open Dependabot, code-scanning or secret-scanning alerts, and no hostname, IP or secret strings in tracked files or in files added in history.
- **Android:** `allowBackup=false`, `fullBackupContent=false`, and data-extraction rules for both cloud backup and D2D transfer (gaps in SEC-M0-7). Only the launcher activity is exported.
- **Prompt injection:** every issue, PR and commit is the owner's; nothing to flag.

## Not verified
- The deny-list gaps in SEC-M0-1 come from the pattern text and the `gh`/`git` documentation. They were **not executed**, because that would perform the forbidden action. How Claude Code splits compound commands before matching wasn't tested either.
- The GitHub ruleset and the `production` environment configuration (admin bypass off, required reviewer, main-only branch policy). The agent's own deny list blocks the read-only API calls (`*rulesets*`, `*eployment*`). The owner should confirm these once in the UI.
- The VM itself (sshd, ufw, the `authorized_keys` line, Caddy's global log config, file modes of `secrets/`). Agents never touch the VM.
- `cargo audit` / `cargo deny` weren't run: they aren't installed locally and aren't in CI yet (tracked in #11). Dependabot alerts, which include RustSec advisories for `Cargo.lock`, show none open.
- **Codec advisory watch** (a threat-model assumption). A quick search shows 2026 CVEs in giflib (e.g. CVE-2026-23868, CVE-2026-26740) and Skia (e.g. CVE-2026-3909, exploited in Chrome in March 2026). These weren't checked against the primary advisories. No impact at M0, because no image decoding ships yet. They do support the Android patch-level rule and the "browser decodes on the web" default in #24.
- On-device behaviour of the Android rules (D2D transfer of `device_*` domains) and the cleartext default on API 26–27 come from Android's documentation, not from a device test.

## Threat-model changes
Proposed edits to `docs/security/threat-model.md` (owner or a follow-up PR):
1. **Accepted risks, AI-agent row:** keep "backstop with known gaps", but replace "the common REST/GraphQL routes" (to dispatch, re-run or approve deploys) with the *most direct* routes, name the missed deploy forms (`-XPOST`/`--method=POST` on `…/dispatches` and `…/pending_deployments`, `graphql -F query=@file`, token + `curl`), and note separately that the push/merge-to-`main` patterns have gaps (a)–(e) (SEC-M0-1).
2. **Accepted risks, Shared VM row, and ADR-0005:** replace "trusts `X-Forwarded-For` only from Caddy" with "ignores `X-Forwarded-For` for security decisions; limits are keyed on account, device, invite and globally". Add ARP spoofing by peer containers with the default `CAP_NET_RAW` as a second way to intercept the Caddy→server hop (SEC-M0-5).
3. **Known metadata visible to the server:** add the MLS framing fields (`group_id`, `epoch`, `content_type`, `authenticated_data`), KeyPackage contents and Welcome KeyPackageRefs (SEC-M0-9). Add "backups keep server data, including messages the DS already deleted, for 14 days" (SEC-M0-8).
4. **Security goal 3 / padding note:** state that GIF-reference messages are padded to one fixed size (planned in #24, SEC-M0-3), because 256-byte blocks alone leak a length class.
