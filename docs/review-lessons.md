# Review lessons

Guidance only: it never overrides `CLAUDE.md` or the agent files. Recurring review-finding types, so they get caught while writing instead of in review. Read at the start of every session. After each PR, add a line for any finding type that could recur; merge duplicates, keep one line per type.

- **Docs drift:** when a decision changes, grep `docs/`, ADRs, open issues, code comments and file headers for the old term and update all of them in the same PR. — #39 CR-2, CR-3, CR-4, CR-10, SEC-6, SEC-13 · #37 SEC-5 · #36 CR-4, SEC-8 · #38 CR-4 · #30 CR-6, CR-7 · #46 CR-1 · #74 CR-1, SEC-55 (a "closed until #N" line survived #N: grep for the issue number too) · #91 CR-1
- **Security claims:** every claim names its adversary (passive vs. active server) and its limits; check platform/browser/GitHub facts (e.g. concurrency semantics, package visibility defaults) against primary docs before writing them down; write planned controls as "Planned (#n)", never as if in place, and don't say "only" unless the list is complete. — #30 CR-1, CR-3, CR-9, SEC-7 · #37 SEC-1, SEC-2, SEC-3 · #39 CR-1, CR-8, SEC-7, SEC-8, SEC-12 · #45 CR-1, CR-2, SEC-3, SEC-4 · #47 CR-2, SEC-14 · #51 SEC-1 · #63 SEC-20, CR-2, CR-3 (a "weekly run" and a "new issue" that didn't exist) · #65 SEC-1, CR-4 ("wiped" without naming the copies that remain) · #77 CR-2 (say what a control protects today, not what a later issue will make it protect)
- **Untrusted fields:** every sender- or server-supplied field (URLs, ids, sizes, names) gets explicit bounds, a validation rule applied to the raw input, and a test. Peers on shared infrastructure (a Docker network or host shared with other services) are untrusted too: no trust in forwarded headers or in hostnames they can claim (a Docker alias), limits enforced by the server itself, and clients of internal services pin strong authentication (pgjdbc `requireAuth=scram-sha-256`). A field whose absence would weaken a check gets no permissive default: missing fails closed, or adding it is a breaking change (ADR-0006). Decoders throw more than their documented exception type (kotlinx: `IllegalArgumentException` for some malformed JSON; Ktor's ContentNegotiation wraps decode errors in `JsonConvertException`), so boundaries catch all of them and map to a closed result. On the client this covers every response body, 2xx included. A shared rule keyed on an identifier (an origin, a URL) applies that identifier's canonical rule first and refuses anything else, instead of string operations that pass `https://host/x.test`. — #39 SEC-1, SEC-3, CR-5, CR-9 · #36 SEC-7 · #30 SEC-4 · #46 SEC-1 · #62 SEC-1, SEC-6, SEC-11 · #69 SEC-15 · #79 plan SEC-3 · #102 CR-1, SEC-14
- **Insecure defaults:** when adding a tool or library, check its security-relevant defaults (padding, panic strategy, caching provider, query suite, lock mode, repository filtering, accepted auth methods, error-log verbosity) and record the chosen value. A "re-pinned on every run" guarantee covers everything that can be granted by hand (role memberships, not just attributes). Tools that execute dependency code in CI (e.g. CodeQL Rust extraction) get locked, pre-fetched dependencies. Feature policies are allow-lists (`exact = true`), not deny-lists, and so are text checks for a marker: list where it may appear, not where it may not (a module-wide opt-in or a wrapper elsewhere gets past a deny-list). — #36 SEC-2, SEC-1 · #35 SEC-2, SEC-6 · #38 CR-2, CR-3, SEC-5 · #45 SEC-5 · #63 SEC-21 · #69 SEC-16, CR-1 · #94 SEC-17
- **IDE/Windows artifacts:** stage explicit paths; IDE edits (`gradle.properties`, `gradle-daemon-jvm.properties`, file modes) must not slip in. The script checks file modes and `toolchainUrl` entries; the rest needs a diff review. — #35 CR-1, CR-2, SEC-1, SEC-7 · #36 CR-4
- **Matching pins:** versions that must match (crate ↔ CLI ↔ CI) are exact (`=`) and cross-referenced in comments. Checked by `scripts/check-repo-hygiene.sh`. — #37 CR-3
- **Claimed behaviour needs a test:** every behaviour the PR body or docs claim ("error arrives as X", "Commit path works") has a test that asserts it. Run container images locally with the production UID and hardening before claiming they work. A fake that returns the answer of a filter or query instead of running it tests nothing about that filter: run the real filter (`jq`, SQL) on realistically shaped data, and smoke-test against the real platform, which adds what fakes don't (the cloud environment appends a footer to PR bodies). A guard test sets up the state the guarded step needs (a stored key, not just an identity), so it fails for the guard's reason, and a mutation check proves it; a scan that can pass on nothing carries a positive control in the same form as what it forbids, and is mutation-checked on a real build (Kotlin/Wasm keeps a package name as `app.gifitup.cli`, so a needle with a trailing dot never matched). — #36 CR-1 · #37 CR-2 · #32 CR-1 · #47 (Ktor workdir crash, found by that test) · #98 smoke test (PR #99) · #103 CR-1, SEC-13, SEC-17, SEC-18
- **Size and error metadata:** lengths and error strings leak; pad payloads and map errors to closed codes before they cross FFI or reach logs. Decoder exceptions (kotlinx `JSON input: …`) echo their input, so their message/cause is never logged, shown or returned. A malformed 2xx body is no exception (a bad `SessionResponse` quotes the token; boundary rule under *Untrusted fields*). — #36 SEC-2, SEC-6 · #30 CR-12, SEC-6 · #62 SEC-2 · #79 plan SEC-3
- **PR accuracy:** the PR body lists every changed area; check the risk-tier table (CLAUDE.md) against your own diff; record owner decisions only with the owner's explicit words, and when you add an item to a list the owner accepted, ask again instead of letting the old acceptance cover it. — #35 CR-2 · #30 CR-11 · #39 SEC-11 · #91 CR-2 · #92 SEC-18
- **Command deny patterns:** block whole classes (a subcommand, any global option, a flag prefix), not single spellings; before claiming coverage, probe flag order, abbreviated long options, aliases, case and wrappers with harmless `--help`/dry-run forms. Text patterns can't stop shell quoting/escaping; claims say "most direct forms" and list known gaps. — #60 CR-1, CR-2, SEC-1–SEC-5, SEC-7–SEC-10
- **Guards across FFI and targets:** wasm-bindgen silently truncates a JS number to the Rust parameter's integer width (257 → `u8` 1, and `u32` wraps modulo 2^32), so a closed set crosses as a string or is range-checked from `f64`; a guard that checks a flag and then runs the call holds a lock across both, so no concurrent call slips in between; and a guarantee that relies on unwinding (`catch_unwind`) needs its own mechanism and test on wasm32, where a panic is a trap that skips Rust code. A trap also skips Kotlin/Wasm's own `catch` and `finally`; only a JavaScript `try`/`catch` around the call sees it. A boundary that maps failures to a closed result catches what every target throws: Ktor's web (fetch) engine fails with `kotlin.Error`, not `Exception`, so catch `Throwable` after rethrowing `CancellationException`. — #63 SEC-18, SEC-19, CR-1 · #66 SEC-1 · #94 CR-2
- **State updates on error paths:** build the new state (a list, a map) aside and assign it only after the whole loop succeeded; never `drain` or `retain` with a fallible check, or one `?` drops entries whose secrets stay stored. Time-based cleanup deletes only what is provably expired, never what merely looks "not yet valid" after a clock jump. Never discard state (a pending key or identity) on an answer that a still-running earlier attempt could contradict: a retry or resume can't tell the earlier attempt didn't commit, so discarding is a user decision; and a use case that persists such state runs one call at a time. — #65 CR-1, CR-2, SEC-4 · #95 CR-2, CR-3, CR-5, SEC-1, SEC-6
- **Build inputs:** a task that consumes an artifact built by a custom task (a native library, a wasm package, files copied into `node_modules`) declares it as an input, or a change to the source alone leaves tests UP-TO-DATE or served from the build cache. Prove it with a source-only change that must fail a test. — #66 CR-1
- **Scan what ships:** checks for test-only code or leaked data run on the final artifacts (APK, web bundle), not only on intermediate outputs, because wiring can change between the two. Release binaries rewrite build-machine paths (`--remap-path-prefix`). — #67 SEC-1, SEC-3, CR-6
- **Tools that install on first use:** when several build tasks call the same tool (cargo through rustup), install it once before the build and serialize the tasks, or a fresh CI runner races itself. — #67 CR-1
- **Framework settings do what the engine does, not what their name says:** read the engine source for a limit or timeout and prove it with a test against the real engine (raw sockets for HTTP), including the idle and half-sent cases. — #68 SEC-15 (Ktor's read timeout never closed idle connections)
- **Protocol state machines:** a handler that tracks request/response state is tested with out-of-order and extra events: a response before the request finished (early rejects, 404, 413), interim responses (`100 Continue`), pipelining. Each case gets a mutation check. — #68 SEC-19, SEC-20
- **Early rejects and error mappings:** an interceptor that answers a call must `finish()` the pipeline, or route-scoped plugins (auth, rate limits) still run; global exception mappings cover only the types a boundary produces, so a server bug (`require` failing) stays a logged 500, never a silent 400. — #68 SEC-16, CR-1, SEC-17
- **Review-finding tracking:** a milestone-review finding that belongs to an existing issue goes into that issue's body (a checklist section) and the issue gets the `review-finding` label; a comment alone doesn't count. — #59 CR-1
- **Dependencies:** declare them `implementation` (not `api`) and only when used. — #32 CR-2, CR-3
- **Seams and safe defaults in persistence:** a value with a security meaning (how an account joined, who created a row) has no default parameter and no test-only variant in production code; every write of one use case goes through the same injected seam, and a write that must hit one row checks the row count. Admin bulk deletes over a tree lock against concurrent inserts, or a row created meanwhile escapes. — #74 CR-2, CR-3, SEC-53, SEC-57
- **Route allow-lists and exemptions:** match the exact HTTP method plus a whole-path pattern, never the path alone or a prefix: another method on the same path, or a sibling route, must not ride along, and templated routes (`/devices/{id}`) must be expressible. Test a non-matching method. — #77 SEC-70, SEC-71, CR-1
- **Narrowing a rule:** when a rule gets a cap, a tier or an exemption, walk every case the old rule covered (each path, each kind of commit after the last review) and say where it lands now; nothing may fall silently out of review. — #90 CR-3, CR-4, SEC-1, SEC-2
- **Text rules on sender-supplied strings:** count and check Unicode code points, never UTF-16 units (`String.length` and `Char.category` see an emoji as two surrogates and miss every non-BMP format character), with one shared fixed table from a pinned Unicode version, never platform tables (JVM, Android and Wasm differ). Name ranges explicitly where parts are unassigned (the tag block), fix the order of check, trim and count, and reject values that only look empty (default-ignorables). — #92 SEC-1, SEC-3, SEC-12, SEC-13, CR-1, CR-2
- **References the server can compute:** a reference that points at content (a message reference for reactions or replies, ADR-0006 B9) but is derived from bytes the server sees can be recomputed by the server, so it stays inside encrypted content and never goes into a server-visible field, header, push payload or log, or the server learns what points at what. A hash over the same bytes that is meant for the server (e.g. a freshness value, #16) is allowed, with its own domain-separation label so it can never equal a reference. — #92 SEC-5, SEC-15
- **Agent text vs. owner consent:** agents post under the owner's account, so a marker can flag agent text, but a missing marker proves nothing; owner decisions count only from chat, quoted and dated. Markers sit where markup can't hide them (first line too, not only after an unclosed `<!--`). — #98 CR-4, SEC-11, SEC-13
- **Check what you send:** copy the input first, then run every check on the copy that actually goes out; a guard whose tool errors (grep status 2) fails closed, never as "no match" (and `xargs` maps that error to the same status as no match, so grep the file list directly). Checks of what may be on a classpath are allowlists, not lists of known bad artifacts. A text check of build files matches every spelling a reference can take: accessors, names in either quote and paths into the directory. — #98 CR-3, SEC-14 · #102 SEC-13 · #103 CR-4, SEC-15
- **Durable means synced:** a store that promises "durable when it returns" fsyncs the file before an atomic rename **and** the directory after the rename or delete (POSIX), and a write path checks the same invariants as its read path (a 32-byte key is refused on save, not only on load). — #102 SEC-15, CR-3
