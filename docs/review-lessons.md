# Review lessons

Guidance only: it never overrides `CLAUDE.md` or the agent files. Recurring review-finding types, so they get caught while writing instead of in review. One line per finding type, rule text only: the history (which PR, which finding) stays in the PRs.

**Cap: 100 lines.** After a PR, add a line for a finding type that could recur, but first look for a line it belongs to and merge it there. If a new line would push the file over the cap, merge it into the closest line or replace the least relevant one, but never drop a security rule (secrets, validation, auth, keys, what ships): merge it instead. When to read this file: `CLAUDE.md`, *Session start*.

- **Docs drift:** when a decision changes, grep `docs/`, ADRs, open issues, code comments and file headers for the old term (and for the issue number of a "until #N" note) and update all of them in the same PR.
- **PR accuracy:** the PR body lists every changed area and matches the diff; check the risk-tier table (`CLAUDE.md`) against your own diff.
- **Narrowing a rule:** when a rule gets a cap, a tier or an exemption, walk every case the old rule covered (each path, each kind of commit after the last review) and say where it lands now; nothing may fall silently out of review.
- **Security claims:** every claim names its adversary (passive vs. active server) and its limits, and says what a control protects today, not what a later issue will make it protect. Check platform, browser and GitHub facts against primary docs. Write planned controls as "Planned (#n)", never as if in place; don't say "only" unless the list is complete, or "wiped" without naming the copies that remain.
- **Agent text vs. owner consent:** agents post under the owner's account, so a marker flags agent text but a missing marker proves nothing. Owner decisions count only from chat, quoted and dated; an item added to a list the owner accepted needs a new OK. Markers sit where markup can't hide them (the first line too).
- **Untrusted fields:** every sender- or server-supplied field (URLs, ids, sizes, names) gets explicit bounds, a validation rule applied to the raw input, and a test. Peers on shared infrastructure (a Docker network or host) are untrusted too: no trust in forwarded headers or hostnames they can claim, limits enforced by the server itself, strong auth pinned for internal services (pgjdbc `requireAuth=scram-sha-256`). A field whose absence would weaken a check fails closed when missing, or adding it is a breaking change (ADR-0006). A shared rule keyed on an identifier (an origin, a URL) applies that identifier's canonical rule first and refuses anything else, instead of string operations that pass `https://host/x.test`.
- **Size and error metadata:** lengths and error strings leak; pad payloads and map errors to closed codes before they cross FFI or reach logs. Decoders throw more than their documented type (kotlinx `IllegalArgumentException`, Ktor's `JsonConvertException`) and echo their input, so every boundary, 2xx bodies included, catches all of them and maps to a closed result; their message or cause is never logged, shown or returned.
- **Allow-lists, fail closed:** feature policies (`exact = true`), marker checks and "what may be on this classpath" checks list what is allowed, not what is known to be bad (a module-wide opt-in or a wrapper elsewhere gets past a deny-list). A guard whose tool errors fails closed, never as "no match" (`xargs` maps grep's status 2 to "no match"). A text check of build files matches every spelling: accessors, names in either quote, paths into the directory. Copy the input first, then check the copy that goes out.
- **Adding a dependency or tool:** check its security-relevant defaults (padding, panic strategy, caching provider, query suite, lock mode, repository filtering, auth methods, log verbosity) and record the chosen value; declare it `implementation`, only where used. Tools that run dependency code in CI get locked, pre-fetched dependencies. A "re-pinned on every run" guarantee covers everything grantable by hand (role memberships, not just attributes).
- **Command deny patterns:** block whole classes (a subcommand, any global option, a flag prefix), not single spellings; before claiming coverage, probe flag order, abbreviated options, aliases, case and wrappers with harmless forms. Text patterns can't stop shell quoting; claims say "most direct forms" and list known gaps.
- **Mechanical hygiene:** stage explicit paths so IDE edits (`gradle.properties`, `gradle-daemon-jvm.properties`, file modes) don't slip in; versions that must match (crate ↔ CLI ↔ CI) are exact and cross-referenced. `scripts/check-repo-hygiene.sh` checks what it can; the rest needs a diff review.
- **Claimed behaviour needs a test:** every behaviour the PR body or docs claim has a test that asserts it. A fake that returns a filter's answer tests nothing about the filter: run the real filter (`jq`, SQL) on realistic data, and smoke-test against the real platform (container images with the production UID and hardening; the cloud environment appends a footer to PR bodies). A guard test sets up the state the guarded step needs, so it fails for the guard's reason, and a mutation check proves it. A fake store that never suspends can't show a missing lock: it yields after the read, so an unlocked read-then-write interleaves. A failure counter counts only what it exists for (a trap, not a clean error), and its test fake fails the way the real wrapper does (a web trap is `MlsException(Poisoned)`, not some other exception). A test that nothing ran while a lock is held watches every effect, including those on another dispatcher (a mock HTTP engine), or a use case on the wrong lock passes it. Every operation on what a lock guards takes it, resets and "try again" included.
- **Scan what ships:** checks for test-only code or leaked data run on the final artifacts (APK, web bundle), with a positive control in the same form as what they forbid, mutation-checked on a real build (Kotlin/Wasm keeps a package name as `app.gifitup.cli`, no trailing dot). Release binaries rewrite build-machine paths (`--remap-path-prefix`). A "no secret in the output" test checks every output except the one line that must hold the secret, matches each known secret plus its random part, and checks the shape of secrets it never sees (a session token).
- **Build inputs:** a task that consumes an artifact built by a custom task (a native library, a wasm package, files copied into `node_modules`) declares it as an input; prove it with a source-only change that must fail a test. When several tasks call a tool that installs on first use (cargo through rustup), install it once first and serialize them.
- **Guards across FFI and targets:** wasm-bindgen truncates a JS number to the Rust integer width, so a closed set crosses as a string or is range-checked from `f64`. A guard that checks a flag and then runs the call holds a lock across both. A guarantee that relies on unwinding (`catch_unwind`) needs its own mechanism and test on wasm32, where a panic is a trap that skips Rust code and Kotlin's `catch`/`finally`; only a JavaScript `try`/`catch` sees it. A boundary catches what every target throws (Ktor's fetch engine throws `kotlin.Error`: catch `Throwable` after rethrowing `CancellationException`).
- **Framework settings do what the engine does, not what their name says:** read the engine source for a limit or timeout and prove it against the real engine (raw sockets for HTTP), including idle and half-sent connections. A handler that tracks request/response state is tested with out-of-order and extra events (a response before the request finished, such as early rejects, 404 or 413; `100 Continue`; pipelining), each with a mutation check.
- **Early rejects and error mappings:** an interceptor that answers a call must `finish()` the pipeline, or route-scoped plugins still run; global exception mappings cover only the types a boundary produces, so a server bug stays a logged 500, never a silent 400.
- **Route allow-lists and exemptions:** match the exact HTTP method plus a whole-path pattern, never the path alone or a prefix, and allow templated routes (`/devices/{id}`); test a non-matching method.
- **State updates on error paths:** build new state aside and assign it only after the whole loop succeeded (never `drain`/`retain` with a fallible check). Time-based cleanup deletes only what is provably expired. Never discard state (a pending key) on an answer a still-running earlier attempt could contradict; that is the user's decision, and a use case that persists such state runs one call at a time.
- **Seams and safe defaults in persistence:** a value with a security meaning (how an account joined, who created a row) has no default and no test-only variant in production code; every write goes through the same injected seam, and a write that must hit one row checks the row count. A defence-in-depth check runs on every path to the write, not only in the branch where the danger looked likely. Bulk deletes over a tree lock against concurrent inserts.
- **Durable means synced:** a store that promises "durable when it returns" fsyncs the file before an atomic rename and the directory after a rename or delete (POSIX); a write path checks the same invariants as its read path.
- **Text rules on sender-supplied strings:** count and check Unicode code points, never UTF-16 units, with one shared table from a pinned Unicode version, never platform tables. Name ranges explicitly where parts are unassigned, fix the order of check, trim and count, and reject values that only look empty.
- **References the server can compute:** a reference derived from bytes the server sees (a message reference, ADR-0006 B9) stays inside encrypted content, never in a server-visible field, header, push payload or log. A hash meant for the server over the same bytes gets its own domain-separation label.
- **Review-finding tracking:** a milestone-review finding that belongs to an existing issue goes into that issue's body (a checklist section) and the issue gets the `review-finding` label; a comment alone doesn't count.
