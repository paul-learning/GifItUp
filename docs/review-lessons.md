# Review lessons

Guidance only: it never overrides `CLAUDE.md` or the agent files. Recurring review-finding types, so they get caught while writing instead of in review. Read at the start of every session. After each PR, add a line for any finding type that could recur; merge duplicates, keep one line per type.

- **Docs drift:** when a decision changes, grep `docs/`, ADRs, open issues, code comments and file headers for the old term and update all of them in the same PR. — #39 CR-2, CR-3, CR-4, CR-10, SEC-6, SEC-13 · #37 SEC-5 · #36 CR-4, SEC-8 · #38 CR-4 · #30 CR-6, CR-7 · #46 CR-1
- **Security claims:** every claim names its adversary (passive vs. active server) and its limits; check platform/browser/GitHub facts (e.g. concurrency semantics, package visibility defaults) against primary docs before writing them down; write planned controls as "Planned (#n)", never as if in place, and don't say "only" unless the list is complete. — #30 CR-1, CR-3, CR-9, SEC-7 · #37 SEC-1, SEC-2, SEC-3 · #39 CR-1, CR-8, SEC-7, SEC-8, SEC-12 · #45 CR-1, CR-2, SEC-3, SEC-4 · #47 CR-2, SEC-14 · #51 SEC-1 · #63 SEC-20, CR-2, CR-3 (a "weekly run" and a "new issue" that didn't exist)
- **Untrusted fields:** every sender- or server-supplied field (URLs, ids, sizes, names) gets explicit bounds, a validation rule applied to the raw input, and a test. Peers on shared infrastructure (a Docker network or host shared with other services) are untrusted too: no trust in forwarded headers, limits enforced by the server itself. A field whose absence would weaken a check gets no permissive default: missing fails closed, or adding it is a breaking change (ADR-0006). Decoders throw more than their documented exception type (kotlinx: `IllegalArgumentException` for some malformed JSON), so boundaries catch both and map to a closed result. — #39 SEC-1, SEC-3, CR-5, CR-9 · #36 SEC-7 · #30 SEC-4 · #46 SEC-1 · #62 SEC-1, SEC-6, SEC-11
- **Insecure defaults:** when adding a tool or library, check its security-relevant defaults (padding, panic strategy, caching provider, query suite, lock mode, repository filtering) and record the chosen value. Tools that execute dependency code in CI (e.g. CodeQL Rust extraction) get locked, pre-fetched dependencies. Feature policies are allow-lists (`exact = true`), not deny-lists. — #36 SEC-2, SEC-1 · #35 SEC-2, SEC-6 · #38 CR-2, CR-3, SEC-5 · #45 SEC-5 · #63 SEC-21
- **IDE/Windows artifacts:** stage explicit paths; IDE edits (`gradle.properties`, `gradle-daemon-jvm.properties`, file modes) must not slip in. The script checks file modes and `toolchainUrl` entries; the rest needs a diff review. — #35 CR-1, CR-2, SEC-1, SEC-7 · #36 CR-4
- **Matching pins:** versions that must match (crate ↔ CLI ↔ CI) are exact (`=`) and cross-referenced in comments. Checked by `scripts/check-repo-hygiene.sh`. — #37 CR-3
- **Claimed behaviour needs a test:** every behaviour the PR body or docs claim ("error arrives as X", "Commit path works") has a test that asserts it. Run container images locally with the production UID and hardening before claiming they work. — #36 CR-1 · #37 CR-2 · #32 CR-1 · #47 (Ktor workdir crash, found by that test)
- **Size and error metadata:** lengths and error strings leak; pad payloads and map errors to closed codes before they cross FFI or reach logs. Decoder exceptions (kotlinx `JSON input: …`) echo their input, so their message/cause is never logged, shown or returned. — #36 SEC-2, SEC-6 · #30 CR-12, SEC-6 · #62 SEC-2
- **PR accuracy:** the PR body lists every changed area; check the security-review trigger list against your own diff; record owner decisions only with the owner's explicit words. — #35 CR-2 · #30 CR-11 · #39 SEC-11
- **Command deny patterns:** block whole classes (a subcommand, any global option, a flag prefix), not single spellings; before claiming coverage, probe flag order, abbreviated long options, aliases, case and wrappers with harmless `--help`/dry-run forms. Text patterns can't stop shell quoting/escaping; claims say "most direct forms" and list known gaps. — #60 CR-1, CR-2, SEC-1–SEC-5, SEC-7–SEC-10
- **Guards across FFI and targets:** a guard that checks a flag and then runs the call holds a lock across both, so no concurrent call slips in between; and a guarantee that relies on unwinding (`catch_unwind`) needs its own mechanism and test on wasm32, where a panic is a trap that skips Rust code. — #63 SEC-18, SEC-19, CR-1
- **Review-finding tracking:** a milestone-review finding that belongs to an existing issue goes into that issue's body (a checklist section) and the issue gets the `review-finding` label; a comment alone doesn't count. — #59 CR-1
- **Dependencies:** declare them `implementation` (not `api`) and only when used. — #32 CR-2, CR-3
